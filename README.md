# 县城康复中心 · 居家训练处方与复诊评估平台

## 原始需求

> 开发县城康复中心居家训练处方与复诊评估平台，可采用 React、Spring Boot 和 MySQL。康复治疗师为脑卒中、骨折术后、颈肩腰腿痛或儿童发育迟缓患者建立档案，录入诊断、关节活动度、肌力、疼痛评分、步态视频、家庭照护人和复诊计划。平台根据治疗师处方生成居家训练任务，包含动作次数、禁忌动作、辅助器具、疼痛阈值和家属观察点。患者或家属每日上传训练完成情况、疼痛变化、异常照片和视频片段；这些反馈会影响治疗师是否维持处方、降低强度、追加线下复诊或提醒医生介入。若患者连续漏练、疼痛升高、动作代偿明显或家属反馈无法陪练，平台会把状态推给康复护士做电话随访。复诊时，治疗师需要看到训练依从性、疼痛曲线、视频纠错记录、器具使用和医保可报销项目，再决定下一阶段处方。医保结算需要结合处方执行、复诊评估和线下治疗记录，避免居家训练和门诊治疗断开。平台还要把治疗师、护士、家属和医生的处理记录串在患者时间线上，复诊时能解释每次处方变化为什么发生。平台还要支持按疾病阶段查看风险，治疗师能区分刚出院、稳定训练和复发预警患者的不同处理节奏。

> 增加疼痛升级处置。患者训练后疼痛超过阈值、出现肿胀麻木或夜间疼痛加重时，平台暂停相关动作并要求家属补充症状、用药和是否摔倒。康复护士先做电话评估，必要时转医生复核；医生确认后，处方会调整为休息、冰敷、影像检查或门诊复诊，医保记录也要标注此次中断原因。医生介入结论会同步给治疗师和家属，相关动作在解除风险前不能继续出现在每日训练任务中。

> 增加照护人更换交接。老人或儿童患者的主要陪练家属更换时，平台要求新照护人完成动作注意事项、禁忌风险和器具使用确认。旧照护人的反馈记录仍保留在患者档案中；治疗师可以比较更换前后的训练依从性和疼痛变化，判断问题来自患者状态变化还是陪练理解偏差。交接完成后，新照护人首周反馈会被重点标记，护士可以判断是否需要额外电话指导。

## 技术栈与架构

- **前端**：React 18 + Vite + Ant Design 5 + ECharts（疼痛曲线/依从性图表）
- **后端**：Spring Boot 3（Java 17）+ Spring Security（JWT）+ Spring Data JPA
- **数据库**：MySQL 8（utf8mb4，仅 compose 内部网络访问，不发布宿主端口）
- **部署**：多阶段 Dockerfile（前端构建 → 后端构建 → JRE 运行时，非 root 用户 + HEALTHCHECK），`docker compose up -d` 一键启动

```
浏览器 ──> app 容器（Spring Boot :8080，同时托管 React 静态资源与 /api）
              │ JDBC（服务名 mysql，内部网络）
              └─> mysql 容器（MySQL 8，不暴露宿主端口）
```

## 快速启动（验证方式 = 宿主 docker compose up）

```bash
cp .env.example .env   # 可选；环境变量已由平台注入时无需此步
docker compose up -d --build
```

- 应用实际映射端口：`docker compose port app 8080`（宿主机端口取 `CC_PUBLISH_PORT`）
- 浏览器访问：`http://localhost:<端口>/`（容器内验证可用 `http://host.docker.internal:<端口>/`）
- 健康检查：`curl http://host.docker.internal:<端口>/actuator/health`
- 首次启动自动建表并注入演示数据（5 位患者、4 类疾病、3 个疾病阶段的完整故事线）
- 停止：`docker compose down`（加 `-v` 可同时清空数据卷）

## 核心业务流程

1. **建档与评估**（治疗师）：患者管理 → 新建档案（诊断/照护人/医保）→ 录入评估（关节活动度、肌力、疼痛 VAS、ADL、步态视频）。
2. **处方生成任务**：开具分阶段处方，每个训练项目含 组数×次数×每日频次、禁忌动作、辅助器具、疼痛阈值、家属观察点、医保编码与单价；新处方自动归档旧处方。
3. **每日打卡**（家属端「今日训练」）：勾选完成项 → 自动算完成率；填训练前后疼痛、能否陪练、是否动作代偿、备注，上传异常照片与训练视频。
4. **规则引擎预警**（打卡时实时 + 每日 7:00 定时扫描）：
   - 训练后疼痛 ≥ 处方疼痛阈值，或较训练前升高 ≥2 分 → 「疼痛升高」
   - 家属标记动作代偿 → 「动作代偿明显」
   - 家属无法陪练 → 「家属无法陪练」
   - 连续 ≥2 天未打卡 → 「连续漏练」（≥4 天升为高风险）
   - 预警自动进入护士随访队列并写入患者时间线。
5. **护士随访**：预警中心接单 → 记录电话随访（内容/结果/后续安排）→ 可转医生或解除；医生填写介入意见。
6. **疼痛升级处置**（闭环，打卡实时触发）：
   - **触发**：训练后疼痛 ≥ 处方疼痛阈值，或家属报告「肿胀/麻木」「夜间疼痛加重」→ 平台立即**暂停相关动作**（家属勾选致痛动作；未勾选时按单项疼痛阈值自动判定）并生成处置单，同时推送护士随访队列；
   - **家属补充**：家属端强制填写 症状表现 / 用药情况 / 是否摔倒（有摔倒须描述经过，且关联预警自动升高风险），护士可代登记；
   - **护士电话评估**：结论二选一 —— 风险可控则解除暂停恢复训练；必要时**转医生复核**（动作保持暂停）；
   - **医生处置**：确认后处方调整为 **休息 / 冰敷 / 影像检查 / 门诊复诊**（可多选；选影像/复诊须定日期并自动同步患者复诊计划），结论**同步治疗师与家属**（时间线 + 家属端横幅 + 工作台计数）；
   - **风险解除前**：被暂停动作不出现在每日训练任务中（家属端置灰划线展示）；医生解除风险后自动恢复；
   - **医保标注**：周期内生成结算单时自动汇总每次中断的日期、原因、暂停动作与处置方式，写入结算单「训练中断标注」（不计费留痕）。
7. **照护人更换交接**（老人/儿童患者）：
   - 治疗师在患者「照护交接」页发起更换（填写新照护人信息与家属账号），患者档案照护人与绑定账号即时切换；
   - **三项确认闸门**：新照护人登录家属端须逐项确认 动作注意事项（剂量/观察点）、禁忌风险、器具使用（内容取自当前处方），确认前打卡接口直接拒绝；
   - 旧照护人历史打卡反馈全部保留在患者档案（按提交人可追溯）；
   - **前后对比分析**：治疗师一键查看更换前 7 天 vs 确认后首周 的依从性/完成率/疼痛对比，平台给出判读提示（数据下滑且此前平稳 → 倾向陪练理解偏差；前后接近 → 倾向患者自身状态变化）；
   - **首周重点标记**：确认后 7 天内新照护人的打卡在患者时间线/家属端/训练反馈中打「新照护人首周」标记；护士在预警随访页看到「首周观察」列表（打卡天数/完成率/疼痛概况），可记录电话指导（写入时间线）。
8. **动作视频纠错任务**（闭环）：
   - 治疗师在「训练反馈」对任意带视频的打卡**打回纠错**：从关键动作点字典（膝关节角度/肩胛代偿/步态拖曳/腰部过伸/肩关节半脱位/骨盆下沉/躯干倾斜等）逐点标注时间点与问题描述，附纠错说明；
   - 患者/家属下次打卡前**必须先观看并确认**纠错内容（存在未确认任务时打卡接口直接拒绝，家属端同步置灰提交按钮）；
   - 确认后下一次带视频的打卡会**自动与旧问题关联**，治疗师在「视频纠错」页新旧视频双屏对比复评，判定**已掌握**（闭环）或**未掌握**（继续纠正）；
   - **连续 2 次未掌握** → 系统自动追加线下复评（提前复诊日期）+ 高风险预警推送护士，并建议治疗师评估降低训练强度。
9. **复诊工作台**（治疗师）：一页看全 训练依从性、疼痛曲线、视频纠错任务、器具使用统计、医保可报销项目 → 录入复诊评估 → 决策（维持/降低强度/追加线下复诊/提醒医生介入）→ 开具下一阶段处方，决策依据写入时间线。
10. **医保结算**：按周期生成结算单 = 居家训练可报销项目（按依从性折算次数）+ 复诊评估费 + 线下治疗记录；按医保类型（职工 80%/居民 70%/新农合 60%）计算报销与自付，可确认归档；周期内疼痛升级中断自动标注。
11. **患者时间线**：建档、评估、处方、打卡、纠错任务、预警、随访、疼痛升级处置、照护交接、医生意见、线下治疗、结算全部按时间串联，每次处方变化都带「为什么」。
12. **风险看板**：按 刚出院/稳定训练/复发预警 三列分组，标注不同处理节奏（每日跟进/每周评估/立即处理），卡片展示依从性、漏练天数、未处理预警与风险原因。
